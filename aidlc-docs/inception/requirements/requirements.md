# 테이블오더 서비스 - 요구사항 문서

## Intent Analysis

- **사용자 요청**: 테이블오더 서비스 신규 구축 (Greenfield)
- **요청 유형**: New Project
- **범위**: System-wide (고객용 UI, 관리자용 UI, 백엔드 서버, 데이터베이스)
- **복잡도**: Complex (멀티테넌트, 실시간 통신, 인증/인가, 다수 기능)

---

## 1. 기술 스택

| 영역 | 기술 |
|------|------|
| 프론트엔드 | React + TypeScript |
| 백엔드 | NestJS + TypeScript |
| 데이터베이스 | PostgreSQL |
| 실시간 통신 | Server-Sent Events (SSE) |
| 인증 | JWT 토큰 기반 |
| 배포 환경 | 로컬 서버 / 온프레미스 |

## 2. 시스템 구성

### 2.1 애플리케이션 구조
- **고객용 프론트엔드**: 별도 React 앱 (QR코드 스캔 → 모바일 브라우저 접속)
- **관리자용 프론트엔드**: 별도 React 앱 (데스크톱 브라우저 기반)
- **백엔드 API 서버**: NestJS 단일 서버 (REST API + SSE)
- **데이터베이스**: PostgreSQL

### 2.2 멀티테넌트 구조
- 하나의 시스템에서 다수 매장을 관리하는 멀티테넌트 아키텍처
- 모든 데이터에 `store_id`를 통한 매장별 격리
- 대규모: 다수 매장, 매장당 테이블 100개 이상 지원

### 2.3 관리자 계정 구조
- 슈퍼 관리자가 하위 관리자 계정을 생성하는 계층 구조
- 슈퍼 관리자: 시스템 전체 관리
- 매장 관리자: 자기 매장만 관리

## 3. 기능 요구사항

### 3.1 고객용 기능 (Customer Features)

#### FR-C01: QR코드 기반 테이블 접속 및 세션 관리
- 각 테이블에 QR코드가 부착되어 있으며, 고객이 스캔하면 모바일 브라우저로 주문 페이지 접속
- QR코드 URL 구조: `https://{domain}/order/{tableToken}` (테이블별 서버 생성 고유 토큰, 추측 불가)
- QR코드 스캔 시 별도 로그인/비밀번호 입력 없이 즉시 메뉴 화면 표시
- 고객 세션 유효 시간: 최대 4시간 (만료 시 QR코드 재스캔 필요)
- 같은 테이블에서 여러 고객이 동시 스캔 가능: 같은 테이블 세션 공유, 장바구니는 각자 별도, 누구나 주문 가능
- 테이블 세션은 첫 주문 시 시작, 관리자가 이용 완료 처리 시 종료

#### FR-C02: 메뉴 조회 및 탐색
- 메뉴 화면이 기본 화면으로 항상 표시
- 카테고리별 메뉴 분류 및 표시
- 메뉴 상세 정보: 메뉴명, 가격, 설명, 이미지
- 카테고리 간 빠른 이동
- 카드 형태 레이아웃, 터치 친화적 버튼 (최소 44x44px)

#### FR-C03: 장바구니 관리
- 메뉴 추가/삭제, 수량 조절
- 총 금액 실시간 계산
- 장바구니 비우기
- 클라이언트 측 로컬 저장 (페이지 새로고침 시 유지)
- 서버 전송은 주문 확정 시에만 수행

#### FR-C04: 주문 생성
- 주문 내역 최종 확인 후 주문 확정
- 주문 성공 시: 주문 번호 표시, 장바구니 자동 비우기, 5초 후 메뉴 화면 자동 리다이렉트
- 주문 실패 시: 에러 메시지 표시, 장바구니 유지
- 주문 정보: 매장 ID, 테이블 ID, 메뉴 목록(메뉴명, 수량, 단가), 총 금액, 세션 ID

#### FR-C05: 주문 내역 조회
- 현재 테이블 세션 주문만 표시 (이전 세션 제외)
- 주문 시간 순 정렬
- 주문별 상세: 주문 번호, 시각, 메뉴/수량, 금액, 상태(대기중/준비중/완료)
- SSE를 통한 주문 상태 실시간 업데이트
- 매장 이용 완료 처리된 주문 제외

### 3.2 관리자용 기능 (Admin Features)

#### FR-A01: 매장 인증
- 매장 식별자 + 사용자명 + 비밀번호 입력
- JWT 토큰 기반 인증
- 16시간 세션 유지, 브라우저 새로고침 시 세션 유지
- 16시간 후 자동 로그아웃
- 비밀번호 bcrypt 해싱
- 로그인 시도 제한

#### FR-A02: 실시간 주문 모니터링
- SSE 기반 주문 목록 실시간 업데이트 (2초 이내) 
- 그리드/대시보드 레이아웃: 테이블별 카드 형태
- 각 테이블 카드: 총 주문액, 최신 주문 미리보기
- 주문 카드 클릭 시 전체 메뉴 목록 상세 보기
- 주문 상태 변경 (대기중/준비중/완료)
- 신규 주문 시각적 강조 (색상 변경, 애니메이션)
- 테이블별 필터링

#### FR-A03: 테이블 관리
- **테이블 등록/관리**: 테이블 번호 설정
- **QR코드 생성**: 테이블별 QR코드 자동 생성, 다운로드/인쇄 기능 제공
- **주문 취소**: 관리자가 잘못된 주문 또는 고객 요청에 의해 주문 취소 가능. 확인 팝업 후 주문 상태를 "취소됨"으로 변경 (DB에서 삭제하지 않고 이력 보존). 총 주문액 재계산
- **테이블 세션 처리**: 
  - 세션 시작 (첫 주문 시) 및 종료 (이용 완료)
  - 세션 종료 = 관리자가 수동으로 "이용 완료" 처리 (결제는 시스템 외부에서 진행 후)
  - 이용 완료 시 주문 내역을 과거 이력으로 이동
  - 테이블 현재 주문 목록 및 총 주문액 0으로 리셋
- **과거 주문 내역 조회**: 테이블별 과거 주문 목록 (시간 역순), 날짜 필터링

#### FR-A04: 메뉴 관리 (MVP 포함)
- 메뉴 CRUD: 등록, 수정, 삭제, 조회
- 메뉴 정보: 메뉴명, 가격, 설명, 카테고리, 이미지 URL
- 메뉴 노출 순서 조정
- 필수 필드 검증, 가격 범위 검증
- MVP에서는 이미지 URL만 지원, 추후 업로드 기능 추가

#### FR-A05: 관리자 계정 관리
- 슈퍼 관리자가 하위 매장 관리자 계정 생성
- 매장 관리자는 자기 매장만 접근 가능

## 4. 비기능 요구사항

### NFR-01: 성능
- SSE 기반 실시간 주문 표시: 2초 이내
- 대규모 동시 접속 지원 (다수 매장, 매장당 100+ 테이블)
- 주문 생성 API 응답 시간: 1초 이내

### NFR-02: 보안
- JWT 토큰 기반 인증 (서버 사이드 검증)
- 비밀번호 bcrypt 해싱
- 로그인 시도 제한 (브루트포스 방지)
- 입력값 검증 (SQL Injection, XSS 방지)
- CORS 정책 설정
- HTTP 보안 헤더 적용

### NFR-03: 데이터 무결성
- 멀티테넌트 데이터 격리 (store_id 기반)
- 주문 트랜잭션 처리
- 세션 기반 주문 그룹화

### NFR-04: 가용성
- 로컬 서버 환경에서 안정적 운영
- 에러 발생 시 graceful degradation

### NFR-05: 유지보수성
- TypeScript 기반 타입 안전성
- 모듈화된 NestJS 백엔드 구조
- 컴포넌트 기반 React 프론트엔드

## 5. 제외 기능 (Out of Scope)

requirements/constraints.md 기반:
- 결제 처리 (PG사 연동, 영수증, 환불, 포인트/쿠폰)
- 복잡한 인증 (OAuth, SNS 로그인, 2FA)
- 이미지 리사이징/최적화, CMS, 광고
- 푸시/SMS/이메일/소리 알림 (모바일 푸시, 브라우저 Web Push Notification 등 - SSE 기반 화면 내 실시간 업데이트로 대체)
- 주방 기능 (주방 전달, 재고 관리)
- 데이터 분석, 매출 리포트, 직원 관리, 예약, 리뷰, 다국어
- 외부 연동 (배달 플랫폼, POS, 소셜 미디어, 지도, 번역)
